## 1. Трассировка s.Trim() и Split(';')
**Исходная строка:** `s = "  Ахметов Ерлан;85 "` *(с учетом пробелов/неразрывных пробелов по краям)*

1. **`s.Trim()`**: Удаляет пробелы по краям строки.  
   * Результат: `"Ахметов Ерлан;85"`
2. **`s.Trim().Split(';')`**: Разбивает строку по разделителю `;`.  
   * Полученный массив строк содержит 2 элемента:

| Индекс массива | Содержимое элемента | Длина строки (`Length`) |
| :---: | :--- | :---: |
| 0 | `"Ахметов Ерлан"` | 13 |
| 1 | `"85"` | 2 |

## 2. Трассировка `int.TryParse` для `line = "Иванов Пётр;70;85;x"`
После `line.Split(';')` получаем массив частей: `["Иванов Пётр", "70", "85", "x"]`.

| Индекс части | Часть строки (`string`) | Результат `int.TryParse` | Значение `out int result` |
| :---: | :--- | :---: | :---: |
| 0 | `"Иванов Пётр"` | `false` | `0` |
| 1 | `"70"` | `true` | `70` |
| 2 | `"85"` | `true` | `85` |
| 3 | `"x"` | `false` | `0` |

* **Что вернёт метод типа `TryParseScores` и почему?**  
  Метод вернет `false` (либо общую неудачу при валидации), так как элементы на индексах `0` (`"Иванов Пётр"`) и `3` (`"x"`) не могут быть корректно сконвертированы в целочисленный тип (`int`). `int.TryParse` возвращает `false`, если строка содержит буквы или недопустимые символы.

## 3. Анализ создания объектов: `string` vs `StringBuilder`
**Исходные данные:** `string s = "";` в цикле `for (int i = 0; i < 4; i++) s += i;`

* **Сколько объектов `string` создаётся?**  
  В C# строки (`string`) являются неизменяемыми (`immutable`). Каждая конкатенация `s += i` создает **новый** объект в памяти.  
  * Изначально: 1 объект (`""`).  
  * Шаг 0 (`i = 0`): создается `"0"` (всего 2).  
  * Шаг 1 (`i = 1`): создается `"01"` (всего 3).  
  * Шаг 2 (`i = 2`): создается `"012"` (всего 4).  
  * Шаг 3 (`i = 3`): создается `"0123"` (всего 5).  
  * **Итого создано:** **5 объектов string**.

* **Сколько объектов создаётся при `sb.Append(i)` в `StringBuilder`?**  
  `StringBuilder` использует внутренний изменяемый буфер. При добавлении элементов он переиспользует существующий буфер (иногда выделяя новый массив символов только при переполнении емкости). Для 4 маленьких итераций создается **1 объект** `StringBuilder` (и 0 новых объектов строк внутри буфера).

| Шаг цикла | Операция со `string` (`s += i`) | Новых объектов `string` в памяти | Операция с `StringBuilder` (`sb.Append(i)`) | Новых объектов `StringBuilder` |
| :---: | :--- | :---: | :--- | :---: |
| Исходно | `s = ""` | 1 (`""`) | `var sb = new StringBuilder();` | 1 |
| i = 0 | `s = "0"` | 1 (`"0"`) | `sb.Append(0);` | 0 |
| i = 1 | `s = "01"` | 1 (`"01"`) | `sb.Append(1);` | 0 |
| i = 2 | `s = "012"` | 1 (`"012"`) | `sb.Append(2);` | 0 |
| i = 3 | `s = "0123"` | 1 (`"0123"`) | `sb.Append(3);` | 0 |

## 4. Почему строка `s` не изменилась после `s.ToUpper()` без присваивания?
Строки в C# являются **иммутабельными (неизменяемыми)** объектами. Метод `ToUpper()` не изменяет исходный объект в памяти, а создает и возвращает **новую** строку с символами в верхнем регистре. Если не сохранить результат обратно в переменную (`s = s.ToUpper();`), ссылка на старый объект в переменной `s` останется прежней, а созданная новая строка просто потеряется (удалится сборщиком мусора).
